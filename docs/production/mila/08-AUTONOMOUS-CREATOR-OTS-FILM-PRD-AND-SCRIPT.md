## The specific real agent task (minimal evidence-bearing slice)

**Task ID:** `MILA-DEMO-001`. **Input:** one consented Fanvue inquiry **or** synthetic test inbox record with known ground truth; one approved content-draft input; one authorized connected social data source or sandbox metrics.  
**Toolchain:** reuse existing Agent Zero/Hermes or supported connected agent infrastructure *only after inspecting current installation and permissions*. Record screen at native resolution with mouse cursor and realistic UI latencies.  
**Task order:** (1) initialize session with owner-approved task and capability policy; (2) open Fanvue or named test inbox; (3) inspect one conversation; (4) produce a context-specific, respectful AI-disclosed reply; (5) submit draft to approval queue, or send *only* if an explicitly authorized, policy-compliant, narrowly scoped sending rule exists; (6) open connected social analytics or labeled sample source; (7) draft one content item and schedule only with approval and platform permissions; (8) export receipt with outcome and timestamps; (9) close cleanly.

**Human controls:** account owner handles identity/KYC and initial account authorization; owner can pause, terminate, revoke session and inspect logs at any point. No financial transfers, purchases, paid messages, PPV price changes, consent changes, mass unsolicited messaging or publication without explicit delegated authorization. Do not bypass CAPTCHAs, bot-detection, login controls or platform restrictions. Prefer documented official Fanvue API/OAuth when available and permitted; browser control only within platform terms and granted permissions.

## Must-have evidence

- **Run manifest:** task ID, UTC timestamps, app names, environment, automation agent version, task policy version, account alias (not credentials).
- **Proof screen capture:** start through completion, uninterrupted or accompanied by clearly marked edit cuts; saved separately from cinematic composite.
- **Event sequence:** each navigation/action, input source reference, draft output hash, permission check, send/publish decision, result or error.
- **Approval:** artifact showing `requires_review`, `approved` or `not_sent`, never fake a human approval.
- **Independent replay:** separate reviewer can read the artifact and reproduce the demo in a test account without asking Mila or the filmmaker to assert the outcome.
- **Data hygiene:** redact all real fan identifiers, chat content, financial balances, access tokens, cookies, unique user identifiers and private notifications. Synthetic examples must be clearly labeled.

## Film/compositing plan

**Step A — reality first, no AI video credits:** capture real cloud-browser/computer actions, 1080p 30fps ideally, from a stable recorder. Design the on-screen sequence so every crucial interaction can be read at 390px mobile. Use two or three safe-to-show UI states; retain raw session as the non-promotional evidence source.

**Step B — physical Mila:** generate or stage **four independent 4–8-second camera shots** using the V5 canonical Mila reference and a single consistent studio/desk/look. Shots: wide walk-in and sit; medium OTS settle; OTS hands and keyboard continuity; final profile turn/smile. The performer is AI-synthetic and visibly disclosed; she is not a real human covertly filmed. Use reference frames and last-frame continuity; no license-burning full 30-second blind generation. One test first, then targeted shots after frame QA.

**Step C — screen replacement:** create a high-resolution planar screen insert in the laptop display area. Track its four corners over time (motion tracking/homography), apply perspective transform, subtle reflection/glare, local brightness and shadows, screen refresh, edge occlusion by the hands, desk and lid. Use actual recorded screen frames, not generator-invented text. Screen/computer events align temporally with Mila's keyboard and trackpad gestures. For each shot, fix tracking drift by comparing first/middle/last frames.

**Step D — voice and sound:** owner-locked spoken voice only; source audio begins as camera reaches laptop (5s); room tone, chair, trackpad and keyboard sounds recorded or licensed; no extra narration from another model. Keep music low enough to preserve intelligibility. Edit audio first, then assemble cuts. Preserve original V5 and V6 clocks.

**Step E — edit and mobile framing:** 9:16 master 1080×1920 if footage supports it, 24–30 fps; a 16:9 crop is secondary, not the master. Ensure at least 8% safe margins for subtitles and interfaces. Use restrained wordmark/end card, captions and persistent AI disclosure. No intrusive fake UI animation obscuring the real session.

## Platform and policy notes (research, not verified user account state)

Fanvue supports fully AI creator accounts, but requires a verified human owner and prominent AI disclosure. Fanvue's documentation describes AI chat and Creator Agent capabilities; claims that “no one else automates fan messaging” are inaccurate. Its API policy requires authorized AI messaging, review/pause/disable controls and nondeceptive disclosure. Therefore the meaningful distinction is **cross-application, owner-controlled execution on a portable cloud computer with auditable outcomes**, not merely using AI replies. Do not imply this technical capability is already working until G1 proof is collected.
